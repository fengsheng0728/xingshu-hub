# corpus/ —— Phase 1 样本语料（知识库检索统一 collection）

## 1. 本目录定位

本目录是 **K-1 / Phase 1 的样本语料**：用仓库内已有的真实内容整理而成，用于
跑通「知识条目 → 切片 → 统一 chroma 集合（layer=knowledge）→ 检索分流回查」
链路，并为后续 golden 集与门禁口径标定提供最小语料基座。

**它不是真实企业知识库。** 真实语料的投喂约定见 §2。本目录内容全部来自仓库
既有文件（来源逐篇标注在 front-matter 的 `source` 字段，清单见 §3），
未编造任何企业制度/客户档案/员工信息。

灌入方式：`python scripts/seed_kb.py --key <manager 的 api_key>`（详见脚本注释）。

## 2. 真实企业文档的投喂约定（扩充到 80-300 篇时执行）

**脱敏规则**（入仓前必过）：
- 人名 → 「用户」
- 主机名 → 占位符（如 `<HOST>`）
- 内网 IP → 占位符（如 `<INTERNAL_IP>`）
- 手机号 / 邮箱 → 掩码（如 `138****1234` / `u***@corp.local`）
- **金额保留**（业务语义必需）

**规模与配比**（目标 80-300 篇，6 类）：

| 类别 | 配比 | 对应 category |
|---|---|---|
| 制度类（考勤/报销/差旅/请假） | 30% | `process` |
| 产品与 SOP（安装/验收/售后流程） | 25% | `product` / `process` |
| 售后政策（退换/维修/质保） | 20% | `policy` |
| 销售话术与竞品对比 | 15% | `sales` |
| 客户常见异议与答复 | 10% | `faq` |
| （现有样本中的售后实例归入售后/问答） | — | `aftersales` |

**每篇要求**：300-2000 字；front-matter 字段如下——

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 条目标题 |
| `category` | 是 | 上表 category 之一 |
| `tags` | 是 | `[a, b]` 行内列表（决定 wiki 归类与检索召回） |
| `source` | 是 | 真实来源标注（文件/系统 + 位置），便于溯源与纠偏 |

front-matter 用 `---` 包裹，极简 YAML 子集（`key: value` + 行内列表），
`scripts/seed_kb.py` 自带解析器，不依赖 pyyaml 语法全集。

## 4. 缺口登记（待投喂，不编造）

6 类配比中以下两类**仓库内没有真实素材**，登记为缺口：

- **制度类（考勤/报销/差旅/请假）**：仓库内无任何真实企业制度文档 → 待客户/业务方提供脱敏后的真实制度文本。
- **销售话术与竞品对比**：仓库内无真实销售话术或竞品资料 → 待投喂。

售后政策类目前只有《退换货政策》一篇真实条目，覆盖率远低于 20% 配比目标，
同样待真实素材扩充。
